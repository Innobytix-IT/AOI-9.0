⚠️ Fan-Projekt-Hinweis
AOI 9.0 Nostalgia ist ein inoffizielles Fan-Projekt und steht in keiner Verbindung zu AOL, Verizon Media, Yahoo oder deren Tochtergesellschaften.

„AOL", „AIM" und „AOL Instant Messenger" sind eingetragene Marken ihrer jeweiligen Eigentümer. AOI 9.0 übernimmt lediglich den Retro-Stil als Hommage an eine vergangene Ära – ähnlich wie Fan-Remakes klassischer Videospiele.

📋 Anleitung
📥 Downloads
🔗 Server-URL
So richtest du deinen eigenen AHPT-Signalserver ein
1
Webspace mit PHP 7.2+ bereitstellen
Du brauchst einen normalen PHP-Webspace (kein VPS, kein Node.js). Anbieter wie Strato, IONOS, All-Inkl oder uberspace reichen völlig aus.
2
Dateien hochladen
Lade aoi_signal.php und .htaccess in ein Verzeichnis deines Webspace hoch. Empfohlen: ein eigener Unterordner, z.B. /AOI/
3
Shared Secret festlegen
Erstelle eine Datei namens aoi_token.php im gleichen Verzeichnis. Inhalt: nur eine Zeile mit deinem Passwort (kein PHP-Tag!). Alle, die sich in dein Netz einloggen wollen, brauchen dieses Passwort.
4
Server testen
Rufe die URL direkt im Browser auf. Du solltest eine JSON-Antwort sehen:
{"ok":true,"server":"AOI 9.0 Signal",...}
5
URL in AOI eintragen
Geh zum Tab Server-URL (oben rechts) und trage deine Server-Adresse ein. Beim nächsten Anmelden verbindet AOI dann über deinen eigenen Server.
🌐 Optional – AOI-Netz: Dein Server kann allein stehen (Insel) oder sich mit dem großen AOI-Netz verbinden. Das wählst du vor dem Download im Tab Downloads mit der Checkbox „Am AOI-Netz teilnehmen". Im Netz-Modus können Nutzer verschiedener Server einander als Buddies hinzufügen.
⚠️ Wichtig: Die Datei aoi_token.php ist dein Netzwerk-Passwort. Gib sie niemals weiter oder lade sie ins Repository hoch. Die mitgelieferte .htaccess sperrt den Direktabruf über den Browser.
Server-Dateien herunterladen
🌐 AOI-Netz (optional)
Im Inselmodus (Standard) ist dein Server völlig autark – für dich, deine Familie, deine Freunde.
Im Netz-Modus verbindet sich dein Server mit dem großen AOI-Netz: Nutzer verschiedener Server können sich gegenseitig finden und miteinander chatten.
Diese URL muss von außen erreichbar sein. Der Root-Server (innobytix-it.de) verwendet sie, um Signale weiterzuleiten.
Die Checkbox-Wahl wird in der heruntergeladenen aoi_signal.php fest eingebaut.
📄 aoi_signal.php
Der Signalserver – das Herzstück. Regelt Anmeldung, Präsenz und WebRTC-Handshake.
🔒 .htaccess
Schützt aoi_token.php und aoi_data/ vor direktem Browser-Zugriff. Im gleichen Ordner wie aoi_signal.php ablegen.
🔑 aoi_token.php (Vorlage)
Textdatei mit dem Netzwerk-Passwort – vor dem Hochladen das Passwort ändern! Diese Datei darf nie öffentlich zugänglich sein.
Server-URL einstellen
Hier kannst du die URL deines AHPT-Signalservers einstellen. Diese Einstellung wird beim nächsten Anmelden verwendet.
Standard-Server (Innobytix):
https://innobytix-it.de/AOI_9/AOI_Treffpunkt/aoi_signal.php

🔒 Datenschutz & Datenverarbeitung ✕
AOI 9.0 ist dezentrale Open-Source-Software – kein zentraler Dienst.
Datenschutzrechtlich Verantwortlicher ist jeweils der Betreiber des Signaling-Servers, mit dem Sie sich verbinden – nicht der App-Entwickler. Für den Betrieb des Servers unter innobytix-it.de gilt: Kontakt über info@innobytix-it.de. Wer einen eigenen Server betreibt, ist selbst verantwortlich.
1. Welche Daten werden verarbeitet?
Daten Wo Wie lange
Screen Name Signaling-Server (Präsenz-Heartbeat) Max. 120 Sek. (TTL), danach automatisch gelöscht
IP-Adresse WebRTC ICE → an Chat-Partner übermittelt Nur während der Verbindung, nicht gespeichert
Chat-Nachrichten Ausschließlich P2P (kein Server) Lokal im Gerätespeicher (localStorage)
Offline-Nachrichten Ausschließlich beim Absender (localStorage) – nie auf dem Server Bis zur Zustellung per WebRTC, dann gelöscht
Dateiübertragungen Ausschließlich P2P (kein Server) Nicht gespeichert – direkt übertragen
E-Mail-Passwort Nur lokal, verschlüsselt Bis zur manuellen Löschung
E-Mail-Inhalte Direkt vom E-Mail-Provider AOI-Server sehen diese Daten nie
2. Eingesetzte Technologien
Technologie Zweck Anbieter
Electron Desktop-Anwendungs-Framework OpenJS Foundation
WebRTC (DTLS/SRTP) P2P-Chat & Dateiübertragung, E2E-verschlüsselt W3C-Standard (im Browser integriert)
STUN-Server NAT-Traversal (öffentliche IP ermitteln) Google LLC (stun.l.google.com)
PHP Signaling-Server Präsenz & WebRTC-Vermittlung Betreiber des gewählten Servers
localStorage Lokale Einstellungen, Buddy-Liste, Nachrichten Nur auf diesem Gerät
Electron safeStorage Verschlüsselte Passwort-Speicherung Windows DPAPI / macOS Keychain
ImapFlow / Nodemailer E-Mail-Empfang (IMAP) und -Versand (SMTP) Direkt zum konfigurierten E-Mail-Provider
3. Wer sieht welche Daten?
🟢 Signaling-Server-Betreiber: Screen Name + Zeitstempel der Online-Präsenz (max. 120 Sek.)
🟡 Chat-Partner: Öffentliche IP-Adresse (WebRTC-ICE, technisch unvermeidbar für P2P)
🟡 Google (STUN): Öffentliche IP-Adresse für NAT-Traversal
🔴 Niemand: Chat-Nachrichten, Datei-Inhalte, E-Mails, Passwörter
4. Ihre Rechte (DSGVO Art. 15–21)
Auskunft & Löschung: Abmelden löscht Ihren Präsenz-Eintrag sofort. Offline-Nachrichten liegen ausschließlich auf Ihrem Gerät und werden nach WebRTC-Zustellung automatisch gelöscht. Wenden Sie sich für weitergehende Anfragen an den Betreiber Ihres Servers.
Datenminimierung: AOI 9.0 überträgt nur das technisch Notwendige. Nachrichten und Dateien verlassen Ihr Gerät ausschließlich verschlüsselt und direkt zum Empfänger.
Portabilität: Alle lokalen Daten liegen im localStorage dieses Geräts und können jederzeit über die Browser-Entwicklertools eingesehen werden.
AOI 9.0 ist quelloffene Software (AGPL-3.0) – Quellcode auf GitHub. Jeder Nutzer kann den Signaling-Server selbst betreiben und ist dann selbst datenschutzrechtlich Verantwortlicher im Sinne der DSGVO Art. 4 Nr. 7.
